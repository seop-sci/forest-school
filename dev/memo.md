## 게임 시계 (1.6.0부터, 하루 제한과 주간 제한은 모두 이걸 써요)

기기 시계를 바꿔서 하루 보상을 또 받는 걸 막으려고 만든 공용 함수예요. `dev/forest-school.html`의 "게임 시계" 칸에 있어요. 새 기능(1.7.0 이벤트 등)에서 날짜나 주차가 필요하면 `Date`나 `todayStr()` 대신 이걸 써요.

| 함수 | 돌려주는 값 | 설명 |
| --- | --- | --- |
| `gameNow()` | 숫자(ms, `Date.now()`와 같은 단위) | 서버 시간을 받았으면 서버 시간이에요(웹과 구글 플레이는 Firebase `.info/serverTimeOffset`, 토스는 `Environment.getServerTime`을 시작할 때와 앱을 다시 볼 때 받아요. 모두 `setServerTime(ms)`로 들어와요). 아직 못 받았으면(오프라인, 토스앱 5.245.0 미만) 기기 시간이지만, 지금까지 본 가장 늦은 시각(`S.clk.last`)보다 뒤로 가면 그 시각에 멈춰요 |
| `gameToday()` | 글자 `'YYYY-MM-DD'` | `gameNow()`의 날짜를 한국 시간(UTC+9) 기준으로. 기기 시간대를 바꿔도 같은 날이에요 |
| `gameWeek()` | 정수 | 한국 시간 월요일 0시에 시작하는 주의 번호. 2026-01-05(월)이 0이에요. 주간 제한은 이 값이 커지면 새 주예요(작아지면 무시) |
| `kstDay(ms)` | 글자 `'YYYY-MM-DD'` | 아무 시각(ms)을 한국 시간 날짜로 바꿔요 (표시용) |

- 저장 칸 `S.clk = { last }`: 지금까지 본 가장 늦은 시각(ms). `gameNow()`가 알아서 갱신하니 직접 건드리지 않아요. 서버 시간이 오면 서버 시간으로 바로잡혀서, 기기 시계가 미래로 틀렸다가 돌아온 사람도 서버가 있는 판에서는 바로 풀려요. 저장을 읽을 때는 기기 시간 + 1년까지만 받아요(망가진 값으로 영영 멈추지 않게).
- 하루 제한 쓰는 법: `if (S.x.day !== gameToday()) { S.x.day = gameToday(); S.x.n = 0; }` 처럼 날짜 글자를 저장해 두고 비교해요. 주간 제한은 `S.x.week !== gameWeek()`.
- 지금 이 시계를 쓰는 곳: 부엉이 보충수업 광고(하루 5번), 출석부, 까치 핫딜, 황금 도토리 광고와 상점(`goldDay`), 블록 퍼즐 판 수(`pzDay`), 오늘의 미션(`dmDay`), 주간 리그와 이번 주 미션(`weekIdx()`는 이제 `gameWeek()`와 같아요. 서버 랭킹 기록의 `week`도 이 번호예요). 날짜나 주차가 필요한 곳은 모두 이 시계예요.
- 주 번호가 뒤로 가면(`lgWeek`, `wkWeek`): 아무것도 하지 않아요. 그래서 같은 주 번호로 주간 보상을 두 번 받거나 이번 주 미션이 다시 열리는 일이 없어요.
- 막지 않는 것: 시계를 계속 앞으로만 돌리는 꼼수(지섭 결정, 2026-10-25). 서버 시간을 못 받는 동안 미래로 갔다가 돌아오면 그 미래 시각에 멈춰 있다가, 서버 시간이 오면 풀려요.
- 시험: `dev/s47test.py` (한국 시간 경계, 시간대 바꾸기, 뒤로 돌리기, 미래로 갔다 돌아오기, 하루 제한 다섯 곳과 오늘의 미션).
- 시험 손잡이: `window.__forest.rt.fakeNow = ms`로 기기 시각을 꾸밀 수 있어요(자동 시험에서만).
