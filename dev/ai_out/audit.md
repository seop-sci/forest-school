## 1. 게임 시계가 뒤로 가면 '하루 횟수'와 '이번 주/이벤트 회차'가 다시 열림

**위치**
- 05-calc-clock.js `gameNow` 129줄(서버 시간을 받으면 `S.clk.last = t`로 그대로 덮어씀)과 133줄(기기 시계 대체)
- `dayRoll` 141줄, `canStamp` 145줄
- 30-missions.js `dmDay` 49줄
- 37-season.js `psSync` 105~106줄
- 36-dex-event.js `evSync` 317~318줄

**무엇이 틀리는지**
- 날이 바뀌었는지 볼 때 모두 `!==`(다르면 새날)로만 비교해요. 그래서 게임 날짜가 **뒤로** 가도 새날로 봐요. 출석, 보충수업, 핫딜, 단축권 광고, 오늘의 미션, 패스 오늘 미션 횟수가 다시 열려요.
- `psSync`는 `S.ps.wk !== w`로만 주를 비교해요. `wkWeek`와 `lgWeek`에는 있는 "주 번호가 뒤로 가면 무시" 방어가 없어서, 주가 뒤로 가면 이번 주 패스 미션을 새로 골라요.
- `evSync`도 회차 key만 다르면 도장과 미션을 0부터 다시 시작해요.
- 뒤로 가는 길이 실제로 있어요. 서버 시간을 받는 판(`timeSrc()`가 참)에서도 `rt.clk0.last`가 0이면(새 학교, clk가 없는 옛 저장) 132줄을 건너뛰고 133줄에서 기기 시계를 그대로 믿어요. 이렇게 앞당겨진 `S.clk.last`는 서버 시간이 오면 129줄에서 실제 시각으로 되돌아가요.

**재현**
1. 웹 판에서 clk가 없는 저장(또는 새 학교)으로 인터넷을 끄고 기기 날짜를 하루 뒤로 돌린 채 켜요.
2. 출석 도장, 오늘의 미션, 보충수업을 받아요. 이때 `S.att.last`는 내일 날짜가 돼요.
3. 인터넷을 켜서 서버 시간을 받으면 `gameToday`가 오늘로 돌아가요.
4. `canStamp`가 참이 되어 오늘 하루 보상을 한 번 더 받아요. 주 경계에서 하면 이벤트 도장 7개와 패스 주간 미션도 다시 받아요.

**확신도:** 중간 (`fresh()`가 clk.last를 0으로 두는지는 보이지 않아요)

**고치는 법**
- 날짜 비교를 "더 늦을 때만 새날"로 바꿔요. 예: `o.day < t`. `canStamp`, `evStampReady`, `psSync`의 주 비교(`w > S.ps.wk`), `evSync`의 회차 비교도 같은 식으로요.
- 133줄의 대체 경로는 `timeSrc()`인 판에서 서버 시간 전에는 쓰지 않게 해요. 예: `rt.clk0.last`가 0이면 `devNow`를 기준으로 삼되 `S.clk.last`를 미래로 올리지 않기.

## 2. 서버 시간을 기다렸다 계산한 자리 비운 보상에서 야간 자율학습 겹침 구간이 어긋남

**위치:** 14-teachers-away-ads.js `awaySettle` 206줄 → `applyAway` 217줄

**무엇이 틀리는지**
- `awaySettle`은 `sec = 지금 - from - skip`(켠 뒤 논 시간 skip을 뺌)으로 넘겨요.
- 그런데 `applyAway`는 겹침 구간을 `[지금 - sec, 지금]`으로 잡아요. 즉 `[from + skip, 지금]`이에요.
- 실제로 비운 구간은 `[from, 지금 - skip]`이에요. 그래서 skip만큼 뒤로 밀린 구간으로 야간 자율학습 겹침(`nsOverlap`)을 재요.

**재현**
1. 고등학교 기숙사에서 야간 자율학습을 켜 두고 밤 0~6시에 앱을 꺼요.
2. 아침 6시에 인터넷 없이 켜서 2시간 놀아요(skip = 2시간).
3. 8시에 인터넷이 이어져 서버 시간을 받아요.
4. 겹침이 0~6시가 아니라 2~8시로 계산돼 야간 보너스가 2시간 모자라요. 반대로 밤이 끝 쪽에 걸린 경우에는 더 많이 줘요.

**확신도:** 높음

**고치는 법:** `applyAway(sec, end)`처럼 끝 시각을 넘겨 받아 `nsOverlap(end - sec*1000, end)`로 재요. `awaySettle`에서는 `end = w.from + sec*1000`을 넘겨요.

## 3. 까치 핫딜과 부엉이 보충수업 창의 남은 시간이 기기 시계(Date.now)를 씀

**위치:** 14-teachers-away-ads.js
- `spawnDeal` 426줄, `updateDeal` 417줄, `renderDeal` 445줄
- `teacherAct` 131줄
- `updateBoostWin` 333·338줄, `boostShown` 331줄, `renderBoostBtn` 345줄

**무엇이 틀리는지:** 켜 둔 채 기기 시계를 뒤로 돌리면 `rt.deal.exp`와 `rt.boostUntil`이 그만큼 먼 미래가 돼요.

**재현**
1. 까치가 와 있을 때 기기 시계를 1시간 뒤로 돌려요.
2. 남은 시간이 "61:xx"처럼 보여요.
3. 그동안 `updateDeal`이 `rt.deal`에서 바로 돌아가서 새 핫딜이 생기지 않아요. 보충수업 창도 같은 식으로 길게 남고, 다음 창을 기다리는 시간이 줄지 않아요.

**확신도:** 높음 (영향은 작아요. 다시 켜면 풀려요)

**고치는 법:** 실행 중 상태(`rt`)의 마감 시각은 `perfNow()` 기준으로 잡아요.

## 4. 토스 판에서 화면을 다시 볼 때마다 서버 시간을 다시 받으며 자리 비운 보상이 겹칠 수 있음

**위치:** 41-hotfix-start.js 224줄 → 05 `setServerTime` 103·109줄

**무엇이 틀리는지**
- 다시 보일 때(`!document.hidden`)는 `was`가 계산돼요.
- 숨긴 동안 `performance.now`가 멈추는 기기(iOS WebView 등)에서는 `t - was`가 숨긴 시간 전체가 되어 `awayApply`로 보상을 줘요.
- 숨김과 보임을 처리하는 다른 코드(보이지 않는 파일, `awayHold`와 `awayStart` 쪽)도 같은 구간을 보상하면 두 번이 돼요.

**재현:** 토스 판에서 앱을 30분 내렸다가 올려요. 자리 비운 보상 창이 두 번 쌓이는지(`pendingSec`가 두 배인지) 봐요.

**확신도:** 낮음 (숨김 처리 코드가 보이지 않아요)

**고치는 법:** 보이게 된 뒤 처음 받는 서버 시간에는 109줄의 보상을 건너뛰는 표식을 둬요. 또는 숨김 처리 쪽 보상과 하나로 합쳐요.

## 5. 켠 채 기기 시계를 바꾸면 웹 판 서버 시간 다시 받기가 기기 시계를 따라갈 수 있음

**위치:** 05 `svrDrift` 121줄 → `SVR.resync`(보이지 않음) → `setServerTime` 109줄

**무엇이 틀리는지**
- `resync`가 Firebase의 `serverTimeOffset` 캐시를 써서 `Date.now() + offset`으로 값을 만들면, 시계를 바꾼 뒤에는 offset이 낡아서 그만큼 미래 시각이 들어와요.
- 그러면 `t - was`가 커져서 `awayApply`로 보상을 받고, `S.clk.last`가 미래로 가서 새날이 열려요.
- 108줄 주석이 말하는 "서버 시간끼리의 차이라 기기 시계로는 늘릴 수 없어요"는 진짜 서버 왕복으로 받을 때만 맞아요.

**재현:** 웹 판에서 켜 둔 채 기기 시계를 8시간 앞으로 돌려요. 1분 안에 자리 비운 보상 창이 뜨고 출석이 열리는지 봐요.

**확신도:** 낮음

**고치는 법:** `resync`는 서버 왕복으로 시각을 받게 해요(예: `ServerValue.TIMESTAMP`를 쓰고 읽기). 또는 109줄 보상은 `perfNow` 차이가 아니라 실제로 숨겨졌던 구간에만 줘요.

## 확신도 높은 것 순서

1. 서버 시간을 기다린 자리 비운 보상의 야간 자율학습 겹침 구간이 skip만큼 어긋남 (2번)

## 1. 기억 놀이에서 시간이 다 되면 맞게 누른 칸 하나를 빼고 점수를 매겨요

- **위치:** `23-exam-battle.js`, `btqPts` (996줄). 원인은 `btqMemShow`의 시간 끝 처리(1033줄)와 `btqMemEnd`(1050줄)에 있어요.
- **무엇이 틀리나:**
  - 9초가 지나면 `btqMemEnd(M, false)`가 불리고 `Z.ok`가 false가 돼요.
  - `btqPts`는 ok가 false이면 "마지막에 누른 칸이 틀린 칸"이라고 보고 `input.length - 1`로 셉니다.
  - 그런데 시간이 다 된 경우에는 누른 칸이 모두 맞았어요. 그래서 맞게 누른 칸이 하나 덜 세어져요.
  - 그 결과 일부러 틀린 칸을 누르는 쪽이 끝까지 기다리는 쪽보다 점수가 높아요. 주석에 적힌 "맞게 누른 칸 비율 × 10점"과도 다릅니다.
- **재현:**
  1. 그리기 종목이 나오고, 색은 3개(초등학교)예요.
  2. 2칸을 맞게 누르고 기다리면 round(10 × 1 / 3) = **3점**이에요.
  3. 같은 상황에서 2칸을 맞게 누르고 세 번째를 일부러 틀리면 input이 3이 되어 round(10 × 2 / 3) = **7점**이에요.
- **확신도:** 높음
- **고치는 방법:** 시간 끝인지 틀린 칸을 눌러 끝났는지 따로 기록해 두세요(예: `Z.miss = true`는 틀린 칸을 눌렀을 때만). `btqPts`에서는 `Z.miss`일 때만 1을 빼면 돼요.

## 2. 시험 주에 왔는데 성적표가 안 나오거나, 받지 않은 성적표가 덮여서 사라져요

- **위치:** `23-exam-battle.js`, `exTick` (45~47줄)
- **무엇이 틀리나:**
  - **(가) 성적표가 안 만들어져요.** 성적표는 "시험 주가 아닌 주"에 `S.ex.cur === exPrev()`일 때만 만들어져요. 시험 주 w에 놀고 그다음 처음 켠 날이 다음 시험 주 w+4이면, 45줄이 먼저 `S.ex.cur = w+4`, `ss = 0`으로 덮어써요. 그래서 w의 성적표는 영영 만들어지지 않아요. 주석의 "그 시험 주에 학교에 왔을 때만"이라는 조건은 채웠는데도요.
  - **(나) 받지 않은 성적표가 사라져요.** 47줄은 `S.ex.rep`이 아직 받지 않은 성적표(`got === false`)여도 새 성적표로 덮어써요. 그래서 도토리와 황금 도토리 보상이 사라져요.
- **재현:**
  - **(가)** 시험 주(월~일) 가운데 하루 접속해 자율학습을 해요. 그 뒤 3주 동안 켜지 않다가 4주 뒤 시험 주에 켜요. 성적표가 나오지 않고, 지난 자율학습 수도 0이 돼요.
  - **(나)** 성적표가 나왔는데 받지 않고 둬요. 다음 시험 주에 접속하고, 그다음 주에 접속하면 옛 성적표가 새 것으로 바뀌어요. 옛 보상은 받을 길이 없어요.
- **확신도:** 높음 (동작은 확실해요. 다만 (가)를 일부러 그렇게 둔 것이라면 설계 쪽에서 확인이 필요해요)
- **고치는 방법:**
  - 45줄에서 cur를 새로 바꾸기 전에, 옛 `S.ex.cur`가 지난 시험 주이고 그 주의 성적표가 없으면 먼저 `exMake(S.ex.cur)`를 만들어 두세요.
  - 47줄은 `S.ex.rep && !S.ex.rep.got`일 때 덮지 않게 하세요. 아니면 덮기 전에 옛 성적표 보상을 자동으로 지급하세요.

## 3. 장터 '깜짝 물건: 간식 뽑기'에서 뽑기가 안 되면 도토리만 생겨요

- **고치는 방법:** snDraw가 비거나 실패를 돌려주면 `S.budget -= snCost(false)`로 되돌리고, 쿠폰과 buy 횟수도 되돌리세요. 아니면 값을 더하지 않고 "공짜로 뽑기" 인자를 넘기세요.

- 원하면 대기 중 표식(`pzUI.ending`)을 두고 그 동안 그만하기 단추를 막아도 됩니다.

### 4. 읽던 책이 저장 읽기에서 지워지면 예약 권수가 사라짐

- **위치:** `21-counsel-elect-lab.js` / `sanitizeStudy2` / 684줄, 687줄
- **무엇이 틀리는지:**
  - `R.at`이 0이나 이상한 값이라 `s.rd.cur`가 지워지면, 687줄의 예약 목록 `q`도 같이 버려져요.
  - 그런데 예약할 때 이미 센 하루 권수 `s.rd.n`은 그대로 남아요. 그날은 예약한 만큼 책을 못 읽어요.
- **재현 방법:** `rd.cur`는 있고 `rd.at`이 0이며 `rd.q`에 2권이 든 저장을 읽어요. 읽는 책도 예약도 없는데 오늘 남은 책이 1권으로 줄어 있어요.
- **확신도:** 낮음 (보통 플레이로는 잘 생기지 않는 저장 상태예요)
- **고치는 방법:** `cur`를 지울 때 `s.rd.n = Math.max(0, s.rd.n - q.length)`로 돌려주거나, `q`의 첫 책을 `cur`로 올려요.

### 5. 비 오는 날 아닌 읽기 시간이 저장 뒤 15분으로 돌아감 (짐작)

- **위치:** `21-counsel-elect-lab.js` / `sanitizeStudy2` / 684줄
- **무엇이 틀리는지:**
  - `s.rd.m = R.m === 10 ? 10 : 0`이라서 10분이 아닌 모든 값은 0이 돼요. 0이면 `rdEnd`에서 15분으로 계산돼요.
  - `rdMinNow`가 10이나 15 말고 다른 값(연구, 선생님 효과 등)을 줄 수 있다면 다시 켤 때 끝나는 시각이 바뀌어요.
- **재현 방법:** `rdMinNow`가 예를 들어 12를 주는 상태에서 책을 읽기 시작하고, 앱을 껐다 켜면 3분 늦게 끝나요.
- **확신도:** 낮음 (`rdMinNow`를 보지 못했어요)
- **고치는 방법:** `Number.isFinite(R.m) && R.m > 0 && R.m <= RD.min ? R.m : 0`처럼 범위로 받아요.

## 2. 소풍 단축권: 표가 저장에 없으면 NaN이 저장됨

- **위치:** 22-picnic-sticker-memory.js, `picnicUseTicket`, 68~69줄
- **무엇이 틀리나:**
  - 검사가 `S.tk[k] < 1`이에요. S.tk에 그 키가 없으면 `undefined < 1`이 false라서 검사를 통과해요.
  - 그러면 `S.tk[k]--`가 NaN을 만들고, 그 값이 save()로 저장돼요.
- **재현 방법:** S.tk에 새 단축권 키가 빠진 옛 저장에서, 소풍 중에 그 단축권 단추를 누르면(data-picnic-tk) 돼요.
- **확신도:** 낮음. sanitize가 TK의 모든 키를 0으로 채운다면 일어나지 않아요. 보이지 않는 파일이라 짐작이에요.
- **고치는 방법:** 검사를 `!(S.tk[k] >= 1)`로 바꿔요.

## 3. 버스 돌아오기 장면을 건너뛰면 S.trip.kids가 줄지 않을 수 있음

- **위치:** 27-reward-scenes.js, `busScene`, 76줄과 78줄
- **무엇이 틀리나:**
  - 'back' 모드에서는 `S.trip.kids`를 애니메이션 안의 `off()`(133줄)에서만 하나씩 줄여요.
  - 그런데 아래 두 경우에는 장면 없이 바로 `then()`을 불러요.
    - 움직임 줄이기(rt.reduced)를 켠 경우
    - 밤이나 수학여행 중(kidsAway())인 경우
  - 부르는 쪽이 then 안에서 S.trip.kids를 0으로 맞추지 않으면, 학생이 버스에서 내리지 않은 채로 남아 수가 맞지 않아요.
- **재현 방법:** 움직임 줄이기를 켜고 체험학습을 보낸 뒤 돌아오게 해요. 이어서 지도 학생 수와 수업료를 확인해요.
- **확신도:** 낮음. 부르는 쪽(체험학습 파일)이 보이지 않아요. 그곳에서 이미 정리하고 있다면 버그가 아니에요.
- **고치는 방법:** 두 빠른 길에서 `mode === 'back'`이면 `S.trip.kids = Math.max(0, S.trip.kids - n); syncKids(true);`를 하거나, 부르는 쪽에서 정리하는지 확인해요.
