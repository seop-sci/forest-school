# 작업 요청: 정보를 보존하며 홈 UI 정리

숲속 동물 학교의 홈 화면을 첨부한 `reference/home_target.png`처럼 정돈해 주세요. 기능·정보를 줄이지 않고 상단 현황판, 퀘스트, 오른쪽 메뉴, 건물 이름표, 하단 탭을 묶고 정렬하는 작업입니다. 분석이나 계획만 제시하지 말고 구현·검증·PR까지 완료해 주세요. main에는 합치거나 직접 올리지 마세요.

## 시작과 범위

1. 저장소 `AGENTS.md`, `CLAUDE.md`, `dev/README.md`, `docs/RELEASE.md`, `docs/TESTING.md`를 먼저 읽으세요. 최신 main에서 `feat/home-ui-cleanup` 같은 별도 브랜치를 만드세요. 인계 자료가 다른 브랜치나 ZIP에 있으면 `art/ui_cleanup/`만 가져오고, 다른 아트·기능 브랜치는 섞지 마세요.
2. 게임 원본은 `dev/forest-school.html`입니다. 루트 `index.html`은 직접 고치지 말고 정해진 빌드로 만드세요. 새 프레임워크나 UI 라이브러리는 필요하지 않습니다.
3. `art/ui_cleanup/`의 README, 디자인 토큰, manifest와 시안을 읽고 현 코드와 대조하세요. 조사 기준은 main 커밋 `0b2404510fb7ad690f3e892d14af9ac575b8dc15`의 1.7.0입니다. 실제 최신 코드에 기능이 더 있으면 그 기능도 보존하세요. 줄 번호 대신 함수와 DOM ID를 다시 찾으세요.
4. 지도·건물·동물 그림, `GEO` 좌표와 배치, 이동 경로, 재화 계산, 퀘스트 조건/보상, 광고, 저장 키/필드, Firebase 설정/규칙은 그대로 유지하세요. 이번 UI 작업에 필요하지 않은 버그 수정이나 기능 추가는 별도 제안으로 남기세요.
5. 시안은 레이아웃·색·정보 위계 참고입니다. 지도와 건물을 시안처럼 다시 배치하거나 OS 상태 표시줄/내비게이션 바를 게임 안에 그리지 마세요. 시안의 숫자·학년·타이머·시설 레벨을 코드에 고정하지 마세요.

## 그림과 스타일

- 새 그림: `new/ic_ui_quest.png`(퀘스트), `new/ic_ui_school_event.png`(학교 행사). 모두 256×256 투명 PNG입니다. 버튼의 실제 표시 크기는 약 28~32 CSS px입니다.
- 기존 그림 18종은 `reuse/`와 manifest에 있습니다. 홈·선생님·미니게임·졸업·상점, 랭킹·도감·이벤트·정수 상점·설정, 도토리·학교 그림과 잎 장식을 현재 `window.FS_IMG` 키로 재사용하세요. 복사본을 재임베드하거나 아이콘을 새로 그리지 마세요.
- 출석 달력, 닫기 X, 접기/펼치기, 평판 별, 학생 수 등은 기존 제어용 SVG를 유지하세요. 새 패널/버튼 바탕·선·진행 막대는 CSS로 만들고 글자·숫자는 실제 DOM으로 표시하세요. 시안을 통째로 배경으로 쓰지 마세요.
- `dev/embed_assets.py`를 먼저 읽으세요. 조사 버전은 `ic_`를 인식하고 새 키를 기존 묶음에 합치므로 `new/`만 임베드 대상으로 쓸 수 있습니다. 필요한 두 키 외 기존 그림 데이터가 바뀌거나 사라지지 않았는지 비교하세요. `reuse/`나 시안·미리보기는 임베드하지 마세요. 게임의 단일 파일·오프라인 및 웹/안드로이드/토스 빌드 체계를 유지하세요.
- 크림색 종이, 짙은 숲 초록, 절제된 금빛, 연두 선택 배경을 사용하세요. `design-tokens.css`는 참고값이며 그대로 전역 적용하는 완제품이 아닙니다. 기존 명시적 light/dark와 시스템 테마 전환에 연결하고 다른 창의 테마를 덮어쓰지 마세요. 홈 전용 스타일은 `.app.on-school` 등으로 한정하세요.
- 기존 표시체 Jua를 제목·숫자에 활용하고 본문은 기존 한글 글꼴 체계를 유지하세요. 숫자는 `tabular-nums`를 사용하고, 전역 글꼴 변경은 피하세요. 평판·재화 등 핵심 값을 지나치게 작은 글씨로 줄이지 마세요.

## 바꿀 화면

### 1. 상단 대시보드

- 여러 겹 알약 테두리를 없애고 하나의 현황판 안에 정렬합니다. 첫 줄은 학교 그림·학교명·학년/연차·연차 점과 출석/설정/닫기, 둘째 줄은 동네 단계·진행 막대·다음 목표, 셋째 줄은 도토리(초당 수입 포함)·평판·학생 수 세 칸입니다. 도토리 칸은 약 50%, 나머지 두 칸은 각각 25%를 시작점으로 하되 실제 문자열에 맞춰 조정하세요.
- 학교명 클릭으로 여는 기존 학교 현황 상세를 유지하세요. 학생 현재/정원, 학교 파워, 연차 안내 등 접힌 상세 정보도 빠뜨리지 마세요. 기존 `#schoolCard`의 키보드 동작·`aria-expanded`·닫기 동작을 유지하세요.
- `#vBudget`, `#vRate`, `#vRepTop`, `#vKidsTop`, `#yearNow`, `#yearDots`, `#yearNote`, `#gradePill`, `#barFill`, `#vNext`와 출석 알림·학교 상세 데이터의 바인딩/포맷을 보존하세요. 큰 수는 기존 `fmt`/`fmt2`와 단위 설정을 그대로 사용하세요.

### 2. 퀘스트 카드

- 메인 퀘스트와 아래 학생 부탁들을 하나의 크림색 카드 바탕에 묶습니다. 메인 줄에는 번호·제목·진행·보상·접기, 다음 줄에 설명, 아래 구분선 아래에 부탁 버튼들을 정렬하세요.
- `#qbRew`는 `qReward(q)`의 **보상**입니다. 시안의 `410만`을 건설 비용으로 해석해 비용으로 바꾸거나 값을 고정하면 안 됩니다. 필요하면 짧은 '보상' 표기를 넣어 의미를 분명히 하세요. 수료증 등 보상 종류, 황금 도토리 보너스, 진행 막대, 완료/받기 상태도 유지하세요.
- `#qRow`, `#qFold`, `#questBar`, `#subBar`, `renderQuestBar()`, `renderSubBar()`, 접힘 상태와 이벤트 위임을 보존하세요. 버튼 안에 다른 버튼을 넣지 마세요. 메인 버튼·접기 버튼·부탁 버튼은 공통 시각 바탕 안의 별도 형제 컨트롤로 두세요.
- 시안의 부탁 3개를 고정하지 말고 실제 부탁 목록을 전부 표시하세요. 공간이 부족하면 줄바꿈하고 높이를 재측정하세요. 완료 보상 받기, 신규 표시, 메인 완료 후 학생 부탁으로 전환하는 동작도 유지하세요.
- 긴 설명을 무조건 잘라 정보를 없애지 마세요. 좁은 화면에서는 설명과 보상 줄을 재배치하거나 줄바꿈하세요. 접기는 사용자가 선택하는 기존 동작으로 유지하고 접힌 상태에서도 번호·진행·펼치기 접근성이 유지되게 하세요.

### 3. 오른쪽 메뉴와 왼쪽 상황 버튼

- 퀘스트·랭킹·도감·이벤트·정수 상점을 하나의 얇은 크림색 세로 레일에 같은 폭·간격으로 정렬하세요. 개별 버튼의 두꺼운 바탕/라벨 상자는 없애고 아이콘+글자를 같은 바탕에 놓으세요. 메뉴 이름·알림 점·현재 활성 상태·기존 `data-tab` 동작을 보존하세요.
- 오른쪽은 `right: 8px`, 폭 48~54px, 아이콘 28~32px, 각 항목 높이 최소 54px를 시작점으로 삼으세요. 좁고 낮은 화면에서도 마지막 메뉴가 하단 탭과 겹치거나 잘리지 않게 하세요. 항목을 숨기거나 '더보기' 뒤로 보내지 마세요.
- 왼쪽 학교 행사는 새 풍선과 실제 카운트다운/열림 상태를 한 작은 카드에 묶습니다. 행사 아이콘은 정보용 그림으로만 교체하고 행사 종류/타이머/클릭 동작은 유지하세요.
- 시안에 안 나왔더라도 보충수업·체험학습·황금 도토리 상점·특식·자동 줍기·까치 핫딜과 행사 중 점수판/타이머가 뜨는 조건·알림은 삭제하지 마세요. 동시에 나타나는 조합에서도 서로 가리지 않게 간격을 마련하세요.

### 4. 건물 이름표와 지도

- 기존 건물 이름표의 크림색 바탕·얇은 초록 테두리·모서리·글자 규칙을 통일하고, 업그레이드 화살표를 작은 금빛 단추처럼 붙입니다. 추천 배지와 중학교 잠금 안내도 유지하세요.
- 이름표는 실제 시설명·레벨/건설/잠금 상태를 그대로 표시하고 기존 건물 열기 대상과 접근성을 유지하세요. 지도 좌표, 섬 크기, 건물 비율, 동물 위치·길찾기는 바꾸지 마세요. 긴 이름은 바탕을 늘리거나 읽을 수 있게 재배치하세요.
- `hudVars()`, `--hud-h`, `--left-h`, `--bot-h`, `visMap()`, `fitMap()`, `festFocus()`와 행사 배치/가림 회피를 확인하세요. UI가 달라진 뒤 바뀐 실제 DOM 경계를 측정해서 가시 범위를 계산하세요. 높이를 예전 상수로 두거나 매 프레임 layout 측정을 반복하지 마세요. 초기 로드·폰트 로드·화면 크기/방향·퀘스트 접기·동적 줄바꿈·홈 복귀 때 재측정하고 필요한 경우 `ResizeObserver`와 rAF로 묶으세요.
- 오른쪽 레일과 왼쪽 상황 카드도 행사 아이템/도토리/이름표의 가림 영역으로 고려하세요. 적절한 지도 패닝과 기존 가림 회피를 활용하고 학교 배치 데이터를 고치는 방식으로 해결하지 마세요. 빈 오버레이는 `pointer-events`로 지도 드래그와 줍기를 막지 않게 하세요. 실제 버튼만 클릭을 받아야 합니다.

### 5. 하단 탭

- 크림색 도크 하나 안에 홈·선생님·미니게임·졸업·상점 다섯 칸을 같은 폭으로 둡니다. 홈 선택은 연두 바탕+짙은 초록 글자, 비선택은 바탕 없이 아이콘과 글자만 사용하세요. 알림 점·지도 안내 화살표·선택 상태와 모든 탭 전환을 유지하세요.
- 선택 스타일은 `.tabs > .tab`처럼 하단 탭에 한정하세요. `.tab` 전역을 바꿔 오른쪽 메뉴나 설정 단추까지 큰 탭으로 만들지 마세요. 홈 외 화면의 창 닫기와 기존 스크롤도 확인하세요.
- 하단 도크 높이는 대략 68~76px에 기기 safe-area를 더하는 정도를 시작점으로 하세요. 손가락 제스처 영역과 겹치지 않도록 `env(safe-area-inset-bottom)`을 반영하세요.

## 반응형·접근성 기준

- CSS px 기준입니다. 시안 이미지의 픽셀 크기를 그대로 모바일 CSS 크기로 쓰지 마세요. 기본 바깥 여백 8px, 블록 사이 6~8px, 패널 안 8~10px, 모서리 16~20px, 테두리 약 1px, 약한 그림자 한 겹이 기준입니다.
- 390px 폭에서 상단 현황판 약 120~140px, 메인+부탁 카드 약 90~115px, 오른쪽 레일 약 52px를 시작점으로 삼되 내용 높이를 제한해 자르지 마세요. 360px와 긴 문자열에서는 줄을 재배치하고, 필요한 세로 공간을 줄바꿈으로 확보하세요. 지도 영역이 남도록 장식과 중복 바탕부터 줄이세요.
- 아이콘이 24~32px여도 터치 영역은 최소 44×44px로 유지하세요. 표시는 제목 약 16~18px, 핵심 값 20~23px, 본문 12~14px, 보조 라벨 11~12px가 기준입니다. 작은 화면에서 전역 scale로 축소하지 마세요.
- 밝은/어두운/시스템 테마, 명시적 사용자 테마, 높은 글자 배율을 모두 확인하세요. 본문 대비 4.5:1, 큰 글자/제어 경계 3:1을 기준으로 실제 합성색을 확인하고 필요하면 참고 토큰을 조정하세요. 색만으로 선택/알림을 표현하지 마세요. 기존 초점 표시·키보드 활성화·aria 라벨·reduced-motion을 보존하세요.

## 확인 방법과 완료 기준
