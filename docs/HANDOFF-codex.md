## 3. 지섭 규칙 (꼭 지켜요)

- 모든 답은 **쉬운 한국어**로, 가운뎃점(·)은 되도록 쓰지 않아요. 게임 안 글도 같아요. 게임 안 알림과 설명은 문장마다 줄을 바꾸고 가운데 정렬.
- 답 끝에 **다음 작업에 맞는 추천 모델**을 적어요.
- "**메모해 줘**"라고 하면 고치지 않고 `dev/memo.md` '아직 반영 안 함'에 적고 "적어 뒀어요(지금 n개)"라고만 답해요(커밋, 가능 여부 확인도 하지 않아요).
- "**가능한지**" 물으면 코드만 읽고 답해요. 고치거나 시험을 돌리지 않아요.
- **시험은 업데이트할 때만** 돌려요(사용량 때문). 작업 중에는 문법 확인(`node --check`)이나 화면 한 장 찍기 정도만.
- 밤 8시~자정(한국 시간)에 시험을 돌릴 때는 `cd dev && PYTHONPATH=noon python3 sNNtest.py`(브라우저 시계를 그날 13시로).
- **main에는 지섭이 "업데이트하자"라고 할 때만** 합쳐요("업데이트하자"는 PR을 main에 합치는 승인까지 포함).
- **게임 안 공지**는 지섭이 고른 줄만 넣어요. 후보를 보여 주고 물어봐요.
- 패치노트(`CHANGELOG.md`, 채팅)는 "1. ○○ 고침"처럼 **번호 붙인 짧은 줄**로.
- **서버 규칙**(`database.rules.json`, `dev/gh_database.rules.json`)을 바꾸면 규칙 파일 전체를 채팅에 붙여 줘요. 규칙에 이메일은 넣지 않아요(저장소가 공개). 3.0.0은 규칙 변경이 없을 예정이에요.
- `config.js`, 안드로이드 앱 ID, 애드몹 ID, 토스 광고 그룹 ID는 지섭이 말하기 전에는 바꾸지 않아요.
- 그림이 필요하면 Codex 작업지시서를 **먼저 채팅에 보여 줘요**(다른 일보다 먼저). 그림에는 글자를 넣지 않아요.
- 명세에 없는 밸런스나 디자인 변경은 하지 않고 "제안"으로만 적어요. 숫자를 바꿔야 하면 먼저 물어봐요.

## 4. 코드에서 알아 둘 것

- 게임 원본은 `dev/forest-school.html` 하나(약 2만 줄, 그림이 base64로 들어 있어 파일이 커요). 고칠 때는 이 파일만. `index.html`은 빌드 결과물이라 손대지 않아요.
- 시험 손잡이는 `window.__forest`(`window.__FOREST_TEST`일 때만). 새 함수를 시험에서 쓰려면 이 목록에 더해요(파일 끝 쪽 `if (window.__FOREST_TEST) window.__forest = {`).
- 새 저장 칸: `fresh()`(또는 `freshBt()` 같은 묶음) 기본값 → `sanitize*()`에서 읽기. 저장 칸 이름이 겹치지 않게(이미 있는 것: ex, lg, gd, nb, gn, bx, cg, sn, es, el, bt, ns, tkd, ces, ffx 등).
- 하루 단위는 `gameToday()`, 주는 `gameWeek()`(기기 시계 대신 게임 시계).
- 그림 넣기: `dev/embed_assets.py`(묶음 FS_IMG300 등). 그림 찾기는 `IMG(k)`, `FSI(k)`.
- 조사는 `eul()`, `iga()`, `eun()`, 큰 숫자는 `fmt()`.
- 메인 퀘스트를 바꾸면 `s37test.py`를 꼭 돌려요(업데이트 때).
- 문법만 빠르게 볼 때: 원본에서 `<script>` 안 게임 코드를 꺼내 `node --check`(그림 묶음 `window.FS_IMG...` 스크립트는 빼고).
