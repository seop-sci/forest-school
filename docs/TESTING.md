## 회귀 시험 s37 (교감 선생님 지원, 1.3.0)

여러 시점의 학교(유치원 처음, 유치원 1년째 4장, 유치원 2년째, 초등 1학년, 초등 4학년)에서:
1. `rate()`가 유한한 양수
2. 모든 메인 퀘스트의 `needCost()`가 유한하고 0 이상이며 10^15 이하
3. 모든 메인 퀘스트의 `qReward()`가 유한하고 0 이상
4. `needCost()`가 학교 상태(시설, 선생님, 가구, 학생, 도토리)를 바꿔 놓지 않음
5. `prepTopUp()`이 상한(수업료 30분치 + 200만) 이하, 돌려준 값만큼만 도토리가 늘어남 (1.4.0에서 Issue #2를 고쳐 엄격하게 검사해요)
6. 초등학교에서는 `prepTopUp()`이 0 (유치원에서만 지원)
7. 1.3.0 버그 자리: 유치원 1년째 4장 상태에서 k5(학생 80명)는 지원 0, q18(초당 도토리 30)은 1억 미만
8. 검사 앞뒤로 `rate()`가 같음
9. 퀘스트를 따라 하는 자동 플레이로 유치원을 6시간 안에 졸업하고, 도토리가 10^9를 넘지 않고, 한 퀘스트에 30분 넘게 막히지 않음

### 고친 제한 (Issue #2, 1.4.0)

- 1.3.0까지는 지원량을 상한으로 자른 뒤 앞 두 자리로 올림해서 상한을 최대 10% 넘을 수 있었어요. 1.4.0부터는 올림이 상한을 넘으면 내림해서 상한 안에 머물고, `s37test.py`도 원래 상한 이하인지 엄격하게 봐요.

마지막 줄이 `PASS`면 통과, `FAIL`이면 실패 항목을 적고 끝 코드 1이에요. 1.2.0 원본에 돌리면 needCost가 10^23까지 나와 FAIL로 잡혀요.

## 기본 확인

```bash
python3 dev/check_rules.py               # CLAUDE.md와 AGENTS.md 공통 규칙 일치
python3 dev/check_templates.py --labels  # Issue 양식이 GitHub 규칙에 맞는지, 쓰는 라벨이 저장소에 있는지 (gh 로그인 필요, --labels 빼면 양식만)
```
Issue 양식은 기본 브랜치(`main`)에 있어야 GitHub의 새 Issue 화면에 나타나요. 작업 브랜치에서는 `check_templates.py`로만 확인할 수 있어요.
