**걸리는 점 (정해야 해요)**

1. **받는 곳**: GitHub Pages는 한 달 100GB까지가 권장 한도예요. 앱 이용자가 한 달에 10MB씩 받는다면 1만 명쯤에서 닿아요. 이용자가 늘면 다른 곳으로 옮길 수 있게 주소를 한 곳(`MAP_WEB`)에서만 정해요.
2. **기기에 남기기**: 지금은 WebView의 기본 저장에만 기대요. 인터넷이 없을 때도 받아 둔 것을 쓰려면 Cache Storage 같은 저장을 써야 하고, 토스 WebView와 안드로이드 WebView에서 되는지 기기로 확인해야 해요. GitHub Pages가 붙이는 저장 기간과 교차 출처 허용 머리말은 이 세션에서 열어 보지 못했어요(seop-sci.github.io가 이 세션의 허용 주소 밖이에요).
3. **주소**: 이야기 그림은 `?v=VERSION`이라 버전이 오를 때마다 다시 받아요. 내용 해시 이름으로 바꿔 한 번만 받게 해야 전송량이 안 늘어요.
4. **데이터**: 설치는 가벼워지지만 플레이하면서 조금씩 받아요(이야기 장면 한 장 약 84KB, 곡 하나 0.4~2MB).
5. **안드로이드**: 플레이 스토어에는 100MB 한도가 없어서 토스만큼 급하지는 않아요.

### 그 밖의 작은 것

- 이야기 장면 48개 가운데 35개가 없는 그림(`st_chNN_o`, `st_chNN_c`)을 먼저 받으려다 실패한 뒤 장 그림으로 돌아가요(`stPicUrl`, 원본 24236줄 둘레). 있는 그림 이름표를 두면 헛된 요청이 없어져요.
- 이야기 그림 주소는 `?v=VERSION`, 지도는 `?v=MAPS_V`라서 버전이 오를 때마다 저장해 둔 그림을 다시 받아요. `img/a`처럼 내용 해시를 이름에 붙이면 바뀐 그림만 다시 받아요.
- `dev/fbtest/game.js`(0.22MB, 2.3.4 때 스크립트 사본)는 부르는 곳을 찾지 못했어요.
- 서비스 워커가 없어요. 웹판을 오프라인으로도 열리게 하려면 따로 설계가 필요해요(후보).
